# Internationalization (ADR-0005)

Every user-visible string and every ARIA string in a component comes from a **message catalog**. English is the default; `pt-BR` ships with the library; consumers can override anything. No string literal may appear in component code.

## Pieces

| Piece                                   | Where                     | Purpose                                                                                                                                                                           |
| --------------------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DSProvider`                            | `src/providers/`          | Root provider. Props: `locale` (default `en-US`), `messages` (overrides keyed by component), `navigate` / `useHref` (RAC `RouterProvider`), `children`. Wraps RAC `I18nProvider`. |
| `defineMessages()`                      | `src/i18n/messages.ts`    | Declares a catalog `{ en, 'pt-BR' }`; the type checker enforces that `pt-BR` has the same keys and function signatures as `en`.                                                   |
| `useMessages(key, catalog, overrides?)` | `src/i18n/useMessages.ts` | Resolves the messages for the active locale.                                                                                                                                      |
| `plural(locale, n, forms)`              | `src/i18n/plural.ts`      | Plural form via `Intl.PluralRules`. For use inside catalog functions.                                                                                                             |
| `useDSLocale()`                         | `src/i18n/useMessages.ts` | The active locale string, for passing to the utilities in `src/utils`.                                                                                                            |
| `useLocale()` (re-export of RAC)        | `src/index.ts`            | `{ locale, direction }`. Use `direction` for RTL decisions; never hand-roll RTL detection.                                                                                        |

## Resolution order

Resolved **per message key**, first defined value wins:

1. per-instance override (the component's `messages` prop)
2. `DSProvider` override for that component key
3. `catalog[locale]` (exact tag, e.g. `pt-BR`)
4. `catalog[language]` (e.g. `pt` for `pt-PT`)
5. `catalog.en`

Unknown or malformed locales fall back to English; they never throw. Without a `DSProvider` everything is `en-US` (components still work, they just do not follow the browser locale).

## Rules for component authors

- One file per component: `<Name>.messages.ts`, exporting `messages` built with `defineMessages`. The catalog is a **module-level constant** (the hook memoizes on its identity).
- The component key passed to `useMessages` is the component's name (`'Pagination'`). It is the key consumers use in `DSProvider messages={{ Pagination: { next: '...' } }}`.
- Messages with values are **functions** (`(n: number) => string`). Plurals call `plural(<catalog locale>, n, forms)`, using the locale of that catalog. Do not build strings by concatenation outside the catalog, and do not use a templating library.
- Give the component a `messages?: MessageOverrides` prop typed `Partial<typeof messages.en>` so each instance can override (`MessageOverrides` is the loose type; narrow it per component).
- Dates, numbers, currency, relative time, sorting and search go through `src/utils` with `useDSLocale()` (see [utilities.md](utilities.md)).
- Tests: render with `renderWithProvider(ui, { locale: 'pt-BR' })` and `{ messages: { Name: {...} } }`; assert the default, the `pt-BR` text, a provider override and an instance override.
- Content rules (sentence case, verb + object buttons, no exclamation marks) apply to the English text, see AGENTS.md section 6. `pt-BR` follows the same tone.

## Example

```ts
// Tag.messages.ts
import { defineMessages, plural } from '../../i18n';

export const messages = defineMessages({
  en: {
    remove: (label: string) => `Remove ${label}`,
    count: (n: number) => plural('en', n, { zero: 'No tags', one: '1 tag', other: `${n} tags` }),
  },
  'pt-BR': {
    remove: (label: string) => `Remover ${label}`,
    count: (n: number) =>
      plural('pt-BR', n, { zero: 'Nenhuma tag', one: '1 tag', other: `${n} tags` }),
  },
});
```

```tsx
// Tag.tsx
import { useMessages } from '../../i18n';
import { messages } from './Tag.messages';

export interface TagProps {
  label: string;
  onRemove: () => void;
  messages?: Partial<typeof messages.en>;
}

export function Tag({ label, onRemove, messages: overrides }: TagProps) {
  const t = useMessages('Tag', messages, overrides);
  return (
    <span>
      {label}
      <button type="button" aria-label={t.remove(label)} onClick={onRemove}>
        x
      </button>
    </span>
  );
}
```

Consumer side:

```tsx
<DSProvider locale="pt-BR" messages={{ Tag: { remove: (label: string) => `Excluir ${label}` } }}>
  <App />
</DSProvider>
```

## Gotchas

- Plural categories differ per language (in `pt-BR`, 0 and 1 are both "one"). Always go through `plural`; use the optional `zero` form for an explicit "None".
- Overrides are not deep merged below the message key: a function override replaces the whole function.
- `DSProvider` canonicalizes the tag (`pt-br` becomes `pt-BR`) and forwards it to RAC, so RAC's own strings (calendar, date field) follow the same locale.
