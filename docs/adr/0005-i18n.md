# ADR-0005: Internationalization

- Status: Accepted 2026-10-31
- Date: 2026-10-31

## Context

The design system is English-first, but products built on it need other locales (pt-BR first). Hard-coded strings in components would make that impossible.

## Decision

English is the default for every built-in string. Each component exports its default messages. `DSProvider` merges overrides by locale and wraps RAC `I18nProvider`. A `pt-BR` catalog is shipped. All formatting uses `Intl`.

## Consequences

- No user-visible or ARIA literals inside component code.
- Every component must declare its messages and test overrides.
- Catalogs must be maintained when strings change.

## Alternatives considered

- Third-party i18n library (i18next, FormatJS): heavier, and RAC already provides locale context.
- English only: blocks the first product.
